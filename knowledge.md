# Рабочий контекст AI Home Modeler

Этот файл необходимо читать в начале каждой рабочей сессии и обновлять после
выполненной работы. Здесь хранится краткая долговременная память проекта; полные
требования и решения находятся в `docs/`.

## Цель продукта

Создать AI-сервис, который превращает исходные данные о жилье в редактируемую
пространственную модель, предлагает проверяемые варианты планировки/стиля и
формирует визуализацию, спецификацию и ориентировочный бюджет.

## Важные решения и допущения

- Сейчас всё в документации имеет статус черновика и подлежит согласованию.
- В MVP: 2D-редактор + AI-preview; полноценный 3D предварительно отложен.
- AI не является источником нормативного заключения; критичные изменения требуют специалиста.
- Каноническая геометрия метрическая и версионируемая.
- До подтверждения региона нельзя окончательно выбирать cloud и data residency.

## Известные проблемы и ошибки

- В предыдущей сессии запрошенные документы фактически не были созданы и
  закоммичены; репозиторий содержал только `.gitkeep`.
- Указанные пользователем PDF находятся по Windows-путям и недоступны внутри
  текущего контейнера. Поиск PDF в `/workspace`, `/tmp` и `/root` ничего не нашёл.
- У git-репозитория не настроен remote, поэтому из этого окружения нельзя выполнить
  `git push`. Можно создать локальный commit и описание pull request; для реальной
  публикации нужно добавить remote/интеграцию GitHub.

## Следующие шаги

1. Получить и поместить исходные PDF в `docs/source/`, затем провести gap analysis.
2. Согласовать аудиторию, первый рынок, MVP, монетизацию и необходимость 3D.
3. Перевести утверждённые решения из `docs/decisions.md` в полноценные ADR.
4. После согласования создать skeleton приложений и CI для vertical slice.

## Правило будущих сессий

Сначала прочитать этот файл и актуальную документацию. После работы добавить дату,
изменения, ошибки, принятые решения и ближайшие действия. Не считать локальный
commit опубликованным, пока не подтвержден remote/push.
После изменений кода или документации обновить граф по
`docs/knowledge-graph.md` и проверить связи новых сущностей с существующими.

- Production cloud, data region и AI-провайдер не выбираются до решения по первому
  рынку; внешние AI-вызовы и реальные пользовательские данные пока не включаются.
- Интервью и usability-сессии не проводились: их результаты нельзя заменять
  синтетическими ответами. Для выхода из этапа 0 нужны реальные участники и
  назначенные product/data/security owners.
- Проверены clean install из `package-lock.json` и frozen sync из `uv.lock`; Ruff,
  Pytest, JSON Schema validation, ESLint, TypeScript, Next production build и npm
  audit проходят. В тестах FastAPI остаются два upstream deprecation warning.
- Полный Docker stack собран и запущен: API, web, PostgreSQL/PostGIS, Redis и MinIO
  достигли healthy; init-job создал bucket и завершился с кодом 0. После проверки
  контейнеры остановлены, volumes сохранены.
- Для исключения конфликтов локальные host-порты изменены на PostgreSQL `15432`,
  Redis `16379`, MinIO `19000/19001`; web standalone явно слушает `0.0.0.0`.
- Визуальный browser QA недоступен в текущей computer-use среде; web проверен по
  production build, container health и HTTP-контенту. Usability-проверка остаётся
  частью реальных сессий этапа 0.
- Product owner подтвердил первый рынок: Россия. Для этапа 0 приняты `ru-RU`, RUB
  и метрическая система; конкретный production-регион, применимые нормы и
  cloud/AI-провайдеры остаются предметом legal/security review.

## 2026-09-17 — синтез пакета I-01 — I-12

- В `docs/research/interviews/` получены 12 записей: 6 собственников до/в начале
  ремонта, 3 после ремонта, 2 дизайнера и 1 эксперт по согласованию.
- Все исходные файлы прямо помечены как моделируемые и содержащие синтетические
  формулировки. Владелец продукта поручил использовать их сейчас как рабочий
  эквивалент интервью; пакет учитывается как `proxy`, без выдачи цитат и выводов
  за подтверждённое внешнее исследование.
- Созданы research index, evidence map и полный синтез. Основная рабочая персона
  сохранена: собственник до/в начале ремонта без постоянного сопровождения
  дизайнера.
- Повторяющиеся сигналы: необходимость проверяемых размеров, единой актуальной
  версии, сравнения вариантов, отделения визуального концепта от технической
  проверки, передачи результата специалисту и минимизации персональных данных.
- Уточнены P0-сценарии и план usability-проверки: происхождение размера,
  условные/реальные габариты, сравнение вариантов, версия для подрядчика и граница
  между предупреждением и нормативным заключением.
- Пакет не отвечает на willingness-to-pay, устройства, accessibility, достаточность
  2D/3D, production-регион и выбор провайдеров. Эти вопросы остаются открытыми.
- Интервью-квота операционно покрыта прямым решением владельца продукта, но при
  финальном gate этапа 0 нужно принять остаточный риск proxy-происхождения либо
  заменить записи фактическими заметками.
