# Реестр архитектурных решений

| ID | Решение | Статус | Обоснование / условие пересмотра |
|---|---|---|---|
| ADR-001 | Начать с модульного монолита и отдельных workers | Предложено | Минимум распределённой сложности; пересмотр при измеримой потребности |
| ADR-002 | Каноническая модель в метрах, версионированный JSON Schema | Предложено | Единый обмен между редактором, AI и экспортом |
| ADR-003 | PostgreSQL/PostGIS + S3-compatible storage | Предложено | Транзакции, геометрия и отделение крупных объектов |
| ADR-004 | Асинхронные идемпотентные jobs для тяжёлых операций | Предложено | Долгие/нестабильные внешние операции не блокируют API |
| ADR-005 | AI Gateway с provider adapters и provenance | Предложено | Контроль стоимости, качества и смена провайдера |
| ADR-006 | Next.js/TypeScript + FastAPI/Python | Требует подтверждения | Удобство web UX и AI/CV экосистемы; проверить компетенции команды |

После утверждения каждое решение следует вынести в отдельный ADR с контекстом,
альтернативами, последствиями и датой принятия.
