# Среды и конфигурация

## Матрица сред

| Среда      | Назначение                        | Данные                    | Развёртывание                     | Доступ                        |
| ---------- | --------------------------------- | ------------------------- | --------------------------------- | ----------------------------- |
| local      | Разработка и контрактные проверки | Только synthetic fixtures | Docker Compose/локальные процессы | Разработчик                   |
| preview    | Ревью pull request                | Synthetic seed, TTL       | Автоматически из PR               | Команда, auth required        |
| staging    | E2E, интеграции, rehearsal        | Обезличенные fixtures     | Продвижение CI-артефакта          | Команда и тестеры             |
| production | Реальные проекты                  | Пользовательские данные   | Manual approval + canary          | Пользователи, least privilege |

Production-данные нельзя копировать в local/preview. Используются синтетические
fixtures или отдельно одобренные обезличенные наборы.

## Local

`.env.example` задаёт безопасные локальные значения. После `make infra` доступны
PostgreSQL/PostGIS, Redis и S3-совместимое хранилище. API и web можно запускать
локально для быстрой перезагрузки либо вместе через Docker Compose.

Для снижения конфликтов с уже установленными сервисами host-порты отличаются от
внутренних: PostgreSQL `15432`, Redis `16379`, MinIO `19000/19001`. Официальный
PostGIS-контейнер зафиксирован как `linux/amd64`; на Apple Silicon Docker запускает
его через эмуляцию.

Секреты в `.env` не коммитятся. Локальные пароли не используются ни в одной
удалённой среде.

## Preview и staging

- отдельные database/schema, bucket prefix и queue namespace на окружение;
- миграции выполняются отдельным job до переключения новой версии;
- seed не содержит реальных планов, адресов или контактов;
- preview автоматически удаляется с согласованным TTL;
- внешние AI-вызовы по умолчанию заменены stub, реальные включаются явно с квотой.

## Production

Один подписанный immutable image продвигается из staging. Релиз включает проверку
совместимости миграций, canary, SLO guard и автоматический rollback приложения.
Миграции данных проектируются так, чтобы rollback приложения не требовал отката БД.

Конкретные cloud, region, KMS, secret manager и observability backend выбираются
после решения по рынку/data residency и фиксируются отдельным ADR.

## Конфигурационные правила

- приложение падает при отсутствии обязательной production-конфигурации;
- feature flags и тарифные лимиты изменяются сервером и аудируются;
- secret values не выводятся в startup log или error telemetry;
- public runtime variables содержат только значения, безопасные для браузера;
- доступ service identity ограничен средой, модулем и требуемыми операциями.
