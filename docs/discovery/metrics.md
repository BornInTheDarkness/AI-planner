# Метрики и аналитический контракт

## North-star proxy этапа MVP

Основной proxy полезности — доля начатых проектов, в которых пользователь сохранил
хотя бы один валидный вариант планировки. Метрика не доказывает качество ремонта,
но связывает импорт, понимание результата и намерение продолжить работу.

## Определения

| Метрика                   | Числитель                                                | Знаменатель                   | Окно          | Цель MVP |
| ------------------------- | -------------------------------------------------------- | ----------------------------- | ------------- | -------: |
| Успешное создание проекта | Проекты с подтверждённой первой spatial version          | Уникальные начатые создания   | 24 часа       |     ≥85% |
| Time to first result p50  | Время от `project_created` до первой валидной variant    | Завершившие генерацию проекты | Сессия/7 дней |  ≤15 мин |
| Открытие результата       | Проекты с `variant_opened`                               | Проекты с успешной генерацией | 7 дней        |     ≥60% |
| Сохранение варианта       | Проекты с ручным `variant_saved`                         | Проекты с успешной генерацией | 7 дней        |     ≥35% |
| Ошибка генерации          | Jobs без опубликованного результата по внутренней ошибке | Jobs с валидным входом        | 7 дней        |      <5% |
| Возврат D30               | Actors с meaningful action на 24–37 день                 | Новые actors с проектом       | Cohort        | baseline |

Пользовательская ошибка или несовместимый бриф измеряются отдельно от внутреннего
сбоя. Повторные события одного проекта не увеличивают project-level conversion.
Гостевой actor получает случайный pseudonymous ID, который не содержит email.

## Минимальный event envelope

```json
{
  "event": "variant_saved",
  "schemaVersion": "1.0",
  "eventId": "01K...",
  "occurredAt": "2026-09-17T10:00:00Z",
  "actorId": "pseudonymous-id",
  "projectId": "project-id",
  "properties": {
    "variantId": "variant-id",
    "spatialModelVersion": 3
  }
}
```

В события запрещено включать адрес, план, изображение, prompt, свободный текст
брифа, email и содержимое ошибки провайдера. Для анализа качества используются
отдельные одобренные datasets с контролем доступа и retention.

## Владение и качество

До выхода из этапа 0 требуется назначить product owner метрик и data owner.
Изменение event schema проходит review, имеет версию и тест. Dashboard показывает
полноту/дубликаты/задержку данных; продуктовые решения не принимаются по метрике с
неизвестным качеством.
