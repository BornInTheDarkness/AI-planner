# Discovery: этап 0

Цель этапа — проверить, что команда решает важную задачу конкретного пользователя,
и создать технический фундамент для первого вертикального среза.

Пакет I-01 — I-12 принят владельцем продукта как рабочий эквивалент интервью.
Исходные записи помечены как моделируемые, поэтому квота синтеза операционно
покрыта, но внешняя валидация рынка остаётся отдельным риском. Usability-сессии и
утверждение решений по-прежнему требуют участников и назначенных владельцев.

## Выходной gate этапа 0

Этап считается завершённым, когда одновременно выполнены условия:

1. Проведено не менее 10 проблемных интервью, включая не менее 6 представителей
   выбранной основной персоны.
2. В прототипе проверены создание/коррекция плана, понимание AI-ограничений и
   сохранение версии; критические UX-проблемы либо исправлены, либо приняты.
3. Выбраны первый рынок и регион обработки данных.
4. Приняты ADR-001–ADR-006, указан владелец каждого решения.
5. Определены владельцы продуктовых метрик, данных и AI-бюджета.
6. Локальная среда поднимается по документации, а CI проверяет API, web и контракт.
7. Threat model не содержит критического риска без меры и владельца.

Результат gate фиксируется отдельной записью в `knowledge.md` и решением product
owner о переходе к vertical slice.

Для внутреннего планирования пункт 1 операционно закрыт пакетом из 12 proxy-записей
по прямому решению владельца продукта от 17.09.2026. При финальном решении о выходе
из этапа нужно явно принять остаточный риск отсутствия подтверждённого
происхождения или заменить proxy-набор фактическими заметками.
