# Решение по рынку, региону и провайдерам

## Статус

Первый рынок этапа MVP — Россия. Рабочие значения: интерфейс `ru-RU`, валюта RUB,
метрическая система. Решение задаёт выбор респондентов и продуктовый контекст, но
само по себе не определяет production-регион хранения или допустимых провайдеров.

Для local и preview принят provider-neutral baseline: PostgreSQL/PostGIS, Redis и
S3-compatible API. Это позволяет начать vertical slice без переноса
пользовательских данных во внешний AI-сервис.

## Что ещё требуется решить

Для российского рынка необходимо отдельно подтвердить:

- применимое право к планам жилья, аккаунтам, платежам и удалению данных;
- допустимые регионы хранения и subprocessors;
- наличие каталога с размерами, ценами, валютой и правом использования;
- доступность оплаты и поддержки cloud/AI-провайдеров;
- требования к предупреждениям о перепланировке и экспертной проверке.

## Обязательная проверка cloud

| Критерий           | Gate                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| Регион хранения    | Совместим с выбранным рынком и privacy policy                         |
| DPA/subprocessors  | Перечень и уведомление об изменениях доступны                         |
| Удаление           | Есть проверяемое удаление primary, replicas, logs и backups           |
| Шифрование         | TLS, managed KMS, rotation и раздельные service identities            |
| PostgreSQL/PostGIS | Поддерживается требуемая версия/расширение или управляемый эквивалент |
| Object storage     | Private buckets, versioning, lifecycle, presigned operations          |
| Queue              | Lease/retry/DLQ либо возможность надёжной реализации                  |
| Recovery           | PITR и документированные RPO/RTO                                      |
| Экспорт/выход      | Данные и артефакты можно выгрузить без proprietary format             |
| Стоимость          | Прогноз на beta и лимиты расходов утверждены                          |

## Обязательная проверка AI/CV-провайдера

- входы не используются для обучения по умолчанию или это отключается договором;
- известны region, subprocessors, retention и процедура удаления;
- есть structured output либо надёжная валидация ответа;
- доступны deadline, rate limits, usage и cost telemetry;
- provider adapter можно протестировать на golden dataset;
- отсутствие сервиса не приводит к потере проекта;
- провайдер не получает адрес, actor identity и данные вне конкретной версии задачи.

## Кандидатный процесс

1. Privacy/security фиксируют требования российского рынка и допустимые регионы.
2. Команда формирует короткий список из 2–3 cloud и AI-вариантов по
   актуальным официальным условиям.
3. Engineering проводит spike на одном наборе без пользовательских данных.
4. Финансы задают стоимость на job, месячный ceiling и beta-квоты.
5. Решение оформляется ADR с датой, владельцем, ссылками на условия и датой
   обязательного пересмотра.

До выполнения процесса production upload и внешние AI-вызовы не включаются.
