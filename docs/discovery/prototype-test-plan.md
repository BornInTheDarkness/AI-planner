# Проверка прототипа редактора

## Что проверяем

Прототип в `apps/web` проверяет информационную иерархию этапов проекта,
редактирование объектов на плане, понимание предупреждений и сохранение версии.
Он не проверяет качество распознавания, AI-генерации или скорость backend.

## Сессия

- 5–7 участников основной персоны, 35 минут на человека.
- Участник работает с прототипом самостоятельно; модератор не объясняет UI.
- Запись экрана и голоса выполняется только с согласия.
- После каждой задачи фиксируются успех, время, ошибки, подсказки и уверенность 1–5.

## Задачи

1. Определить, на каком этапе находится проект и сохранены ли изменения.
2. Выбрать диван и переместить его ближе к окну.
3. Задать дивану точную ширину 210 см.
4. Объяснить предупреждение о проходе и предложить следующее действие.
5. Сохранить новую версию и объяснить, что произойдёт с предыдущей.
6. Найти переход к брифу и сказать, чего пользователь ожидает от следующего экрана.

## Порог решения

| Сигнал                       |                      Порог |
| ---------------------------- | -------------------------: |
| Задачи 1–5 без помощи        |      ≥80% успешных попыток |
| Перемещение объекта          |         медиана ≤30 секунд |
| Понимание предупреждения     |         ≥4 из 5 участников |
| Понимание версии             |         ≥4 из 5 участников |
| Критическая ошибка или тупик | 0 повторов у ≥2 участников |

Проблема считается критической, если пользователь не может продолжить, рискует
потерять работу либо принимает предупреждение за нормативное заключение.

## Протокол результата

Для каждой проблемы записываются наблюдение, частота, тяжесть, затронутый сценарий,
предлагаемое изменение и ссылка на принятое решение. После итерации повторно
проверяются только изменённые или связанные задачи; старые результаты не
переносятся автоматически.
