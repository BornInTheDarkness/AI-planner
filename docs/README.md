## Правила ведения

1. Изменение требований сопровождается обновлением критериев приёмки.
2. Существенные технические решения фиксируются в реестре решений.
3. После каждой рабочей сессии обновляется корневой `knowledge.md`.
4. Диаграммы хранятся как Mermaid/текст, чтобы изменения были видны в Git.
5. Версии документов меняются после согласования смыслового блока.
6. Происхождение research-данных фиксируется явно. Proxy-материалы можно
   использовать для рабочей приоритизации только с описанием ограничений; они не
   становятся внешним подтверждением гипотез без отдельного решения о риске.

## Допущение

Упомянутые исходные PDF-файлы отсутствуют в репозитории и файловой системе
рабочего окружения. Поэтому этот комплект создан как самостоятельная исходная
версия и требует сверки с бизнес-моделью и архитектурным roadmap после загрузки
PDF в `docs/source/`.
